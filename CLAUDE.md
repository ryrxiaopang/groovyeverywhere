# Hidden Gems — project guide for Claude Code

A music **recommendation** research kit. It analyses Creative-Commons / royalty-free songs with Essentia
models (Sound, Instruments, Mood, Rhythm), stores the numbers, and recommends "hidden gems" (obscure songs
that sound like a seed song). See `README.md` for the full story and the mentor's test questions.

**Core principle — no audio is ever kept.** Every song is downloaded into a temporary folder, analysed, and
the folder is deleted immediately. Only numbers (embeddings) and metadata are stored. Preserve this in any
change: all downloads go through `sources.temp_audio()`, which uses a `TemporaryDirectory`.

## Platform (important)
Runs on **Linux / WSL2 Ubuntu only** — `essentia-tensorflow` has no Windows or Apple-silicon wheel.
On Windows, do everything inside WSL Ubuntu. Do **not** try to `pip install` or run the analysis on native
Windows or in the Claude Code Windows shell; use the WSL terminal.

## Setup (in WSL, inside this folder)
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
sudo apt-get install -y ffmpeg          # needed by Essentia decoding and by yt-dlp -x
python models.py                        # downloads the Essentia models (~60-180 MB; not in git)
python synthetic_tests.py               # offline self-check, ends "all scoring checks passed"
```

## Data sources (recommendation pool)
- **Jamendo / Audius** — only tracks the site marks downloadable. `sources.py`, `build_pool.py`.
- **FMA** research dataset — streamed one song at a time. `fma_pool.py`.
- **YouTube** — lowest-view music videos per genre, to fix the instrumental skew and add popular vocal
  genres (K-pop, Korean R&B, Mandopop, …). Metadata via the YouTube Data API; audio via yt-dlp, deleted
  straight after analysis. Tagged `source=youtube`, `licence=youtube-standard` (or `creativeCommon`).

### Grow the pool with YouTube songs
```bash
python build_youtube.py --list-genres                 # see / pick genres
python build_youtube.py --per 40 --max-views 100000   # writes/extends pool_youtube.csv (metadata only)
nohup python -u run_tests.py --list pool_youtube.csv > pool_youtube.log 2>&1 &
```
`build_youtube.py` is additive and resumable (merges into `pool_youtube.csv`, skips songs already listed or
analysed). Low-view picks rank as obscure, so `scoring.pick_hidden_gems` surfaces them as gems.

## Validate the models first
Use **MTG-Jamendo** as the sealed test/validation set. Do not add YouTube (or any pool) songs to a test
split. Run `python run_tests.py` on `edge_cases.csv`, then `python evaluate.py` → `report.html` for PASS/WARN/
FAIL per test. Only after the models check out, grow the recommendation pool.

## Storage
PostgreSQL + pgvector is the app's store (`schema.sql`, `setup_db.sh`, `import_results.py`). `results/` holds
the raw per-song `.npz` record and can rebuild the DB. Neither `results/` nor the DB is in git (regenerable,
per-machine). `python similar.py "<song>"` tests recommendations.

## What is NOT in this repo (download/generate locally)
`results/`, `.venv/`, Essentia models (`python models.py`), the big `*.zip` snapshots, generated pool lists
(`pool_*.csv`, regenerated by the build scripts), logs. The MTG-Jamendo `data/*.tsv` **is** included.
